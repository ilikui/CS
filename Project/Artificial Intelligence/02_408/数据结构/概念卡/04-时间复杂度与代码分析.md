# 时间复杂度与代码分析

> 408 数据结构 · 第 01 章原子化概念卡。建议先独立完成自测，再查看解析。

## 一句话定义

时间复杂度描述算法基本操作次数随输入规模 n 增长的趋势。分析时先建立操作次数 T(n)，再提取渐近增长阶。

## 常见增长阶

从低到高：
$$O(1)<O(\log n)<O(n)<O(n\log n)<O(n^2)<O(n^3)<O(2^n)<O(n!)$$

## 代码分析方法

**常数循环：**
```c
x = a[0];
```
固定数量操作，Θ(1)。

**单层循环：**
```c
for (int i = 0; i < n; i++) work();
```
执行 n 次，Θ(n)。

**倍增循环：**
```c
for (int i = 1; i < n; i *= 2) work();
```
满足 2^k ≥ n 时停止，k=Θ(log n)。

**双重循环：**
```c
for (int i = 0; i < n; i++)
  for (int j = 0; j < n; j++) work();
```
执行 n² 次，Θ(n²)。

**三角形循环：**
```c
for (int i = 0; i < n; i++)
  for (int j = 0; j <= i; j++) work();
```
总次数为 1+2+…+n=n(n+1)/2，Θ(n²)。

顺序语句的代价相加后保留最高阶项；分支要按题目要求分析最好、最坏或平均情形；嵌套循环应按边界求和，不能只数循环层数。

## 费曼学习法

把时间复杂度想成“任务量随订单数增长的趋势”。订单翻倍时，线性任务大致翻倍；若两层都遍历全部订单，任务量大致变成四倍。

**复述练习：** 解释倍增循环为什么是对数级，并推导三角形循环的求和式。

**边界提醒：** O(n²) 不等于实际运行时间一定是 O(n) 的四倍；复杂度描述渐近趋势，不包含硬件和常数因子比较。

## 西蒙学习法

按五个微技能训练：
1. 找输入规模 n。
2. 选定基本操作。
3. 计算循环次数。
4. 建立求和式或递推式。
5. 化简并写明分析情形。

每一题必须写出 T(n)，不能只凭代码外观猜复杂度。

## SQ3R 阅读法

- Survey：先浏览四类循环代码。
- Question：循环变量乘 2 为什么是 log n？三角形循环为什么不是 n² 次精确执行？
- Read：逐行追踪边界和循环变量。
- Recite：关掉笔记，推导 n、log n、n² 三类代码。
- Review：当天重做错题，隔天用新代码验证。

## 康奈尔笔记

| 线索问题 | 主体笔记 |
|---|---|
| 时间复杂度？ | 基本操作次数随输入规模增长的趋势 |
| 基本操作？ | 用于计数的代表性操作，如比较或循环体 |
| 倍增循环？ | 2^k≈n，因此 k≈log₂n |
| 双重全循环？ | n×n=n² |
| 三角形循环？ | 1+…+n=n(n+1)/2 |
| 顺序语句？ | 复杂度相加，保留最高阶 |
| 分支？ | 按题意分析指定情形，最坏情况取最大代价 |

**页底总结：** 复杂度分析的关键不是数循环层数，而是计算基本操作次数。写出 T(n)，再化简为渐近阶。

## 自测与解析

1. 两层各执行 n 次的嵌套循环：Θ(n²)。
2. i 从 1 开始每次乘 3，直到大于 n：Θ(log n)。
3. 1+2+…+n：n(n+1)/2，因此 Θ(n²)。
4. T(n)=5n²+3n+8：Θ(n²)。
5. 两段顺序代码分别 Θ(n) 与 Θ(n log n)，合计：Θ(n log n)。

**掌握标准：** 对单层、倍增、双重、三角形循环能写出执行次数；能解释每一步化简依据。
