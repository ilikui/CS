# 数据结构基本概念与抽象数据类型 ADT

> 408 数据结构 · 第 01 章原子化概念卡。建议先独立完成自测，再查看解析。

## 一句话定义

数据结构研究数据元素及其相互关系，以及在这些数据上可实施的操作；抽象数据类型（ADT）进一步把“数据对象、数据关系、基本操作”作为统一的逻辑规范描述。

## 核心知识

| 名称 | 含义 | 学生管理示例 |
|---|---|---|
| 数据 | 客观事物的符号表示 | 学号、姓名、成绩等信息 |
| 数据元素 | 数据的基本单位 | 一名学生的完整记录 |
| 数据项 | 数据元素中不可再分的字段 | 学号、姓名 |
| 数据对象 | 性质相同的数据元素集合 | 全体学生记录 |
| 数据结构 | 元素及其关系的集合 | 学生记录按学号组织的表 |
| ADT | 数据对象、关系和操作的抽象规范 | List 的插入、删除、查找 |

ADT 的典型描述包含三部分：数据对象、数据关系、基本操作。ADT 不规定必须使用数组还是链表实现。

## 关键区分

- 数据类型通常规定值的集合及允许操作；ADT 更强调抽象的数据对象、关系和操作规范。
- ADT 是“对外行为契约”，数据结构实现是“内部组织方式”。
- 同一个 List ADT 可以由顺序表或链表实现；接口语义可以一致，时间/空间复杂度却可能不同。

## 费曼学习法

把 ADT 解释成自动售货机：使用者看到按钮和商品选择规则，不需要知道机器内部是怎样存放商品数据的。只要“查询、购买、取消”等操作符合约定，内部可以换成不同实现。

**复述任务：** 不看资料，用 60 秒解释“为什么 ADT 不等于数组”。必须举出一个 ADT 的两种实现，并说明它们操作效率可能不同。

**反例边界：** 不能说 ADT 完全不关心数据关系；数据关系本身就是 ADT 描述的一部分。

## 西蒙学习法

把知识拆成三个块：
1. 术语层：数据、元素、项、对象。
2. 关系层：数据元素之间如何组织。
3. 操作层：ADT 对外提供哪些操作。

先掌握术语，再理解关系，最后用 List、Stack、Queue 举例。练习时把题目中的对象、关系、操作分别圈出。

## 康奈尔笔记

| 线索问题 | 主体笔记 |
|---|---|
| 数据元素？ | 数据的基本单位，通常由若干数据项组成 |
| 数据项？ | 数据元素中具有独立含义的最小字段 |
| 数据对象？ | 性质相同的数据元素集合 |
| ADT 三要素？ | 数据对象、数据关系、基本操作 |
| ADT 与实现？ | ADT 规定行为，具体实现选择存储组织与算法 |

**页底总结：** 数据结构描述元素及关系；ADT 用数据对象、关系和操作形成抽象规范。实现可以变化，但必须保持对外操作语义。

## 自测与解析

1. 一条学生完整记录是什么？学号是什么？——记录是数据元素，学号是数据项。
2. ADT 的三要素是什么？——数据对象、数据关系、基本操作。
3. List ADT 能否由数组和链表分别实现？——可以；接口语义可相同，效率不同。
4. ADT 是否规定内存必须连续？——不规定，连续与否属于具体存储实现。

**掌握标准：** 能正确区分六个术语；能独立写出一个 ADT 的三要素；能解释抽象规范与具体实现的差别。
