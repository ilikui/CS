# 28｜顺序查找与折半查找

## 一句话定义
顺序查找逐个比较；折半查找利用有序性，每次将候选区间缩小约一半。

## 核心原理
- 顺序查找：从头到尾（或按实现从尾到头）逐项比较，不要求数据有序。
- 折半查找：维护闭区间 [low, high]，取 mid；相等则成功，小于/大于目标时舍弃一半区间。
- 折半查找要求关键字有序，并能高效随机访问中间元素；典型载体是有序顺序表，不适合直接用于单链表。

## 复杂度与 ASL
- 顺序查找最坏 O(n)；成功且 n 个记录等概率、目标必定存在时，ASL=(n+1)/2。
- 折半查找最坏 O(log n)，每次比较后候选规模约减半。
- ASL 是比较次数的期望：ASL=Σpᵢcᵢ，必须先明确成功/失败概率与比较次数口径。

## 例题
长度为 7 的有序表，查找关键字 6（下标从 1 开始）：mid=4，比较后转向右半区 [5,7]；再取 6，第二次命中。注意不同 mid 取整约定可能影响具体比较路径，但不改变对数级复杂度。

## 五法学习
1. **费曼**：顺序查找像逐个点名；折半查找像猜数字，但只有名单已排序且能直接翻到中间页才成立。

## 易错边界
- 折半查找不能直接用于无序表或普通单链表。
- 区间更新必须保证 mid 不再进入下一轮，避免死循环。
- 成功 ASL 与失败 ASL 的计算对象不同，不能混用。
- 折半查找的 O(log n) 不代表所有有序结构都能达到该复杂度；还要看访问中间元素的代价。

## 自测
1. 折半查找的两个关键前提是什么？
2. 长度为 11 的表，顺序查找成功且等概率、目标必定存在，ASL 是多少？
3. 为什么单链表即使有序，也不适合直接折半查找？

**答案**：1. 关键字有序、支持高效随机访问；2. (11+1)/2=6；3. 单链表定位中间结点需从头遍历，无法在 O(1) 时间访问 mid。

## C 语言实现与查找区间跟踪

### 顺序查找

```c
int sequential_search(const int a[], int n, int key) {
    for (int i = 0; i < n; ++i)
        if (a[i] == key) return i;
    return -1;
}
```

### 折半查找（升序数组）

```c
int binary_search(const int a[], int n, int key) {
    int low = 0, high = n - 1;
    while (low <= high) {
        int mid = low + (high - low) / 2;
        if (a[mid] == key) return mid;
        if (a[mid] < key) low = mid + 1;
        else high = mid - 1;
    }
    return -1;
}
```

使用 `low + (high-low)/2` 避免直接计算 `(low+high)/2` 时可能发生的整数溢出。函数返回下标；若题目要求第一个相等元素，需要改为记录候选位置并继续向左收缩。

### 跟踪表

数组 `[1, 3, 5, 7, 9, 11, 13]` 查找 9：

| 轮次 | low | high | mid | a[mid] | 下一步 |
|---|---:|---:|---:|---:|---|
| 1 | 0 | 6 | 3 | 7 | low=4 |
| 2 | 4 | 6 | 5 | 11 | high=4 |
| 3 | 4 | 4 | 4 | 9 | 命中 |

失败查找时，循环终止条件是 `low > high`，此时插入位置（lower_bound）与普通失败返回值不是同一个接口语义。

### 真题变式

若数组含重复值 `[1,2,2,2,4]`，普通折半查找可能返回任意一个 2；若题目要求最左边的 2，命中后仍需令 `high=mid-1` 并记录答案。
