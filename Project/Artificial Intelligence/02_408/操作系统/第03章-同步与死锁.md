## 02. 临界资源与临界区

临界资源是一次只允许一个进程使用的共享资源。访问临界资源的程序片段称为临界区。

同步：多个进程为完成共同任务而协调执行次序；互斥：同一时刻只允许一个进程进入临界区。

临界区管理应满足：空闲让进、忙则等待、有限等待。让权等待强调等待时避免持续占用 CPU。

## 03. 软件与硬件互斥方法

软件算法包括 Peterson 等算法；硬件方法包括关中断（受适用范围限制）、Test-and-Set、Swap 等原子指令。原子指令可实现自旋锁，但忙等会消耗 CPU。

## 04. 信号量与 P/V 操作

信号量是通过原子操作访问的同步原语。P（wait）申请资源，资源不足时等待；V（signal）释放资源或唤醒等待进程。不同教材对信号量数值和队列实现可能有不同约定，做题时按题目定义执行。

互斥信号量初值为 1：

~~~text
semaphore mutex = 1;
P(mutex);
critical_section();
V(mutex);
~~~

同步信号量通常初值为 0：事件完成方执行 V(S)，等待方执行 P(S)。

### 生产者—消费者

缓冲区大小为 $N$，设 mutex=1、empty=N、full=0：

~~~text
producer:
    produce(item);
    P(empty);
    P(mutex);
    insert(item);
    V(mutex);
    V(full);

consumer:
    P(full);
    P(mutex);
    item = remove();
    V(mutex);
    V(empty);
    consume(item);
~~~

先申请资源计数信号量，再申请互斥锁；释放时先释放互斥锁，再增加另一类资源计数。错误顺序可能造成死锁。

## 05. 管程

管程将共享数据、操作和同步机制封装在一起，通常同一时刻只允许一个进程在管程内活动。条件变量用于等待特定条件；wait 阻塞并释放管程互斥权，signal 用于唤醒等待者，具体语义依教材或实现。

## 06. 死锁与四个必要条件

死锁是多个进程因竞争资源而陷入相互等待、无法继续推进的状态。四个必要条件：
1. 互斥：资源一次只能由一个进程使用；
2. 占有并等待：持有资源同时请求新资源；
3. 不可剥夺：资源不能被强制收回；
4. 循环等待：存在进程资源等待环。

四个条件必须同时成立才可能发生死锁。破坏任一必要条件可预防死锁。

## 07. 死锁处理策略

- 预防：通过制度破坏至少一个必要条件。
- 避免：动态判断分配后是否仍处于安全状态，典型算法为银行家算法。
- 检测：允许死锁发生，定期检查资源分配图或等待图。
- 解除：终止进程、撤销部分进程或剥夺资源。

安全状态表示存在一个安全序列，使所有进程都能按序完成；不安全状态不等于已经死锁。

## 08. 银行家算法

核心数据：
- Available：当前可用资源向量；
- Max：最大需求；
- Allocation：已分配资源；
- Need：尚需资源。

$$
Need=Max-Allocation
$$

安全性检查：令 $Work=Available$，反复寻找满足 $Need_i\le Work$ 的未完成进程，将其标记完成并更新 $Work=Work+Allocation_i$。若所有进程都能完成，则系统安全。

资源请求还需检查请求量是否超过 Need 和 Available，再试分配并执行安全性检查。

## 09. 常见失分点

1. 混淆同步与互斥。
2. P/V 顺序错误，或没有保护共享缓冲区。
3. 忘记 empty=N、full=0。
4. 将不安全状态直接等同于死锁。
5. 银行家算法只看 Available，不逐步更新 Work。
6. 死锁四个必要条件与预防策略对应不清。

## 13. 本章五大经典学习法｜同步、互斥与死锁

### 13.1 费曼学习法：解释为什么并发程序需要“排队规则”

多个进程并发访问共享数据时，执行顺序不可完全预测。如果两个进程同时修改同一变量，最终结果可能依赖具体交错顺序，这就是竞态风险。同步负责协调执行次序，互斥保证同一时刻只有一个执行流进入临界区。

- **临界资源**：一次只允许有限执行流使用的共享资源。
- **临界区**：访问临界资源的代码片段。
- **信号量**：通过原子 P/V 操作实现资源计数、互斥和同步。
- **管程**：把共享数据、操作和同步约束封装起来。
- **死锁**：多个进程相互等待对方持有的资源，所有进程都无法继续。
- **安全状态**：存在一个可让所有进程依次完成的安全序列；不安全不等于已经死锁。

**费曼复述练习：**

1. 用共享打印机或共享账户解释互斥和同步的区别。
2. 为什么 P/V 操作必须是原子的？
3. 生产者—消费者中 empty、full、mutex 的初值分别是什么？
4. 为什么 P(empty) 应先于 P(mutex)？
5. 为什么不安全状态不一定已经发生死锁？

**边界提醒：** P/V 的阻塞队列与信号量数值约定可能因教材而异；解题以题目定义为准。写 PV 时必须完整写出初值、执行顺序和释放路径。

### 13.2 西蒙学习法：按同步原语和死锁处理拆分

| 模块 | 内容 | 前置关系 | 达标练习 |
|---|---|---|---|
| A. 临界区 | 共享资源、竞态、互斥/同步、临界区要求 | 进程并发 | 找出共享变量和临界区 |
| B. 信号量 | P/V 原子操作、互斥信号量、同步信号量 | A | 写互斥与前驱约束 PV |
| C. 经典问题 | 生产者消费者、读者写者、哲学家就餐等 | B | 写完整伪代码并验证执行路径 |
| D. 管程 | 共享数据封装、条件变量 wait/signal | B、C | 将信号量方案转换为管程思路 |
| E. 死锁 | 四条件、预防/避免/检测/解除、银行家算法 | A—D | 判断死锁并逐步更新 Work |

**刻意练习路径：**

1. 先画出共享资源和进程关系。
2. 定义每个信号量的含义与初值。
3. 按“申请资源→进入临界区→释放资源”的顺序写 P/V。
4. 逐条模拟可能执行路径，检查是否出现互斥失效、永久等待或资源计数错误。
5. 银行家算法逐轮写 Work、Need、Allocation、Finish，不跳过中间状态。

### 13.5 康奈尔笔记法：同步与死锁线索卡

| 左侧线索 / 问题 | 右侧主体笔记 |
|---|---|
| 互斥？ | 同一时刻只允许一个进程进入临界区。 |
| 同步？ | 多个进程按任务要求协调执行次序。 |
| 临界区要求？ | 空闲让进、忙则等待、有限等待；让权等待可避免忙等。 |
| P/V？ | P 申请资源或等待；V 释放资源或唤醒等待者，均须原子执行。 |
| 生产者消费者初值？ | mutex=1，empty=N，full=0。 |
| 为什么先 P(empty) 再 P(mutex)？ | 先确认有空位，再进入互斥区，避免持锁等待资源导致死锁。 |
| 管程？ | 封装共享数据、操作和同步；条件变量支持等待/唤醒。 |
| 死锁四条件？ | 互斥、占有并等待、不可剥夺、循环等待。 |
| 安全状态？ | 存在一个安全序列，能使所有进程依次完成。 |
| Need？ | Need=Max−Allocation。 |
| 银行家安全性检查？ | Work=Available，找到 Needᵢ≤Work 的进程后释放其 Allocationᵢ 并更新 Work。 |

**页底总结：** 同步题先定义资源与事件，再确定信号量含义和初值，最后检查 P/V 顺序及所有路径。死锁题要区分必要条件、处理策略和安全状态；银行家算法必须逐步更新 Work。

### 13.6 五法融合自测

1. 临界区管理的三项基本要求是什么？
2. 缓冲区大小为 8，生产者—消费者模型中 empty、full、mutex 初值分别是多少？
3. 为什么 P(empty) 通常放在 P(mutex) 前？
4. 死锁四个必要条件是什么？
5. 不安全状态是否意味着系统已经死锁？
6. Max=(7,5,3)，Allocation=(2,1,1)，Need 是多少？
7. 银行家算法中找到一个满足 Needᵢ≤Work 的进程后，Work 如何更新？
