# 第 01 章｜操作系统概述与运行环境

> 本章目标：建立操作系统的整体模型，能够解释操作系统“管理什么、如何提供服务、何时从用户态进入内核态”，并完成系统调用、中断异常与启动过程的基础分析。

## 1. 操作系统的定位

操作系统（Operating System，OS）是管理计算机硬件与软件资源、控制程序执行并向用户和应用程序提供服务的系统软件。它既是资源管理者，也是应用程序与硬件之间的接口。

### 1.1 四类核心资源

| 资源 | 操作系统管理内容 | 典型机制 |
|---|---|---|
| 处理器 | 分配 CPU 时间，组织并发执行 | 进程/线程、调度、中断 |
| 存储器 | 分配、回收和保护内存 | 地址空间、分页、虚拟内存 |
| 文件 | 组织持久化数据及访问权限 | 文件系统、目录、缓存 |
| 设备 | 统一设备访问并协调 I/O | 驱动、中断、DMA、缓冲 |

### 1.2 操作系统的主要功能

1. 处理器管理：进程创建、撤销、调度、同步与通信。
2. 存储器管理：内存分配、地址转换、保护和扩充。
3. 文件管理：文件组织、存取、共享与保护。
4. 设备管理：设备分配、驱动、缓冲和 I/O 控制。
5. 用户接口：命令接口、图形接口和程序接口。

## 2. 操作系统的特征

- **并发**：多个程序在同一时间段内交替或重叠推进。单核 CPU 上通常通过调度实现宏观并发。
- **共享**：多个进程共同使用系统资源。共享分为互斥共享与同时访问（并非所有资源都可真正并行使用）。
- **虚拟**：把物理资源抽象为多个逻辑资源，例如虚拟处理器、虚拟内存。
- **异步**：程序执行具有不确定性，进程推进速度和完成顺序可能不同。

并发与共享互为条件：资源共享需要协调并发访问；并发执行也依赖资源分配与保护机制。

## 3. 内核态、用户态与特权指令

处理器通常至少区分用户态（目态）和内核态（管态）。

- 用户态运行普通应用程序，权限受限，不能直接执行特权指令或任意访问受保护资源。
- 内核态运行操作系统内核代码，可以执行特权操作，例如修改页表、控制设备和设置中断屏蔽。
- 用户程序需要操作系统服务时，通过系统调用请求内核代为执行。

**关键辨析：**系统调用不是普通函数调用。它会触发受控的处理器特权级转换；内核完成服务后再返回用户态。

## 4. 中断、异常与系统调用

### 4.1 中断与异常

| 类型 | 产生来源 | 常见例子 | 典型特点 |
|---|---|---|---|
| 外中断（中断） | CPU 外部事件 | 时钟中断、设备 I/O 完成 | 通常与当前指令流异步 |
| 异常（内中断） | CPU 执行指令时检测到的事件 | 缺页、除零、非法指令 | 与当前指令相关 |
| 陷阱/系统调用 | 程序主动请求或调试机制 | read、write 等系统服务 | 有意触发受控入口 |

不同教材对“陷阱”“软中断”的分类术语略有差异，答题时应先说明采用的分类口径。

### 4.2 中断处理的基本过程

1. CPU 在允许的检查点识别中断/异常。
2. 保存必要的程序状态（如断点地址、状态寄存器）。
3. 根据中断向量定位处理程序入口。
4. 切换到内核态，执行处理程序。
5. 恢复现场并返回，或按异常类型终止/重启相关指令。

中断的核心价值是让 CPU 不必持续轮询外设，并为操作系统获得处理器控制权提供机制。

### 4.3 系统调用的执行路径

应用程序调用库函数 → 参数准备与系统调用号设置 → 执行系统调用指令 → 进入内核态 → 内核检查参数和权限 → 执行服务 → 返回结果与用户态。

注意区分：
- 库函数：用户态代码封装，可能不触发系统调用。
- 系统调用：操作系统提供的内核服务入口。
- API：面向程序员的接口约定，不一定与某个系统调用一一对应。

## 5. 操作系统结构

- **简单结构/整体式内核**：服务集中，调用开销小，但模块边界和维护性较弱。
- **分层结构**：按层次组织功能，上层依赖下层，便于设计和验证，但层次划分可能带来额外开销。
- **微内核**：尽量把服务移到用户态服务器，内核保留最基本机制；模块隔离性好，但进程间通信开销可能增加。
- **模块化内核**：内核可按需加载模块，兼顾性能与扩展性。
- **外核/虚拟机监控器等结构**：以不同方式管理硬件抽象与隔离，理解其设计目标即可。

## 6. 操作系统的发展脉络

| 阶段/类型 | 主要目标 | 典型特征 |
|---|---|---|
| 手工操作 | 完成单个作业 | 人工装卸程序，CPU 利用率低 |
| 单道批处理 | 减少人工干预 | 作业成批执行，内存中通常只有一道作业 |
| 多道批处理 | 提高资源利用率 | 多道程序驻留，CPU 与 I/O 可重叠 |
| 分时系统 | 交互与响应 | 时间片轮转，多用户共享计算机 |
| 实时系统 | 满足时间约束 | 强调确定性与截止期限 |
| 个人/网络/分布式系统 | 资源共享与服务扩展 | 图形交互、联网、并行与分布式协作 |

多道程序设计的关键是：当一道程序等待 I/O 时，操作系统调度另一道程序运行，从而提高 CPU 和设备利用率。

## 7. 程序装入与链接

### 7.1 三种装入方式

1. **绝对装入**：程序中的地址已确定，装入指定内存位置；适用于地址固定的简单环境。
2. **可重定位装入（静态重定位）**：装入时根据实际内存位置修改地址，装入后位置通常固定。
3. **动态运行时装入**：执行时进行地址转换，程序可在运行期间移动，需硬件地址转换支持。

### 7.2 三种链接方式

- 静态链接：装入前把目标模块和库代码合并，生成完整可执行文件。
- 装入时动态链接：装入时再解析外部引用并链接。
- 运行时动态链接：程序运行到需要某模块时再装入/链接，利于共享和节省内存。

## 8. 虚拟机与系统启动

虚拟机通过虚拟化层向上提供近似独立计算机的执行环境。系统虚拟机可运行完整操作系统；进程虚拟机则为单个程序提供运行环境。

典型启动链路可概括为：上电复位 → 固件初始化硬件并选择启动设备 → 引导加载程序装载内核 → 内核初始化内存、设备和调度子系统 → 启动首个用户态进程/服务 → 提供登录或应用环境。不同平台的固件、引导程序和初始化细节存在差异。

## 9. 本章易错点

1. 并发不等于并行：并发强调一段时间内多个任务推进，并行强调同一时刻多个执行单元同时运行。
2. 共享不等于无条件同时访问：临界资源通常需要互斥或同步。
3. 用户态程序不能直接执行特权指令；需要通过系统调用等受控机制请求服务。
4. 外中断通常异步于当前指令，异常通常与当前指令执行相关。
5. 系统调用是内核服务入口，不等同于普通库函数。
6. 静态重定位发生在装入时；动态运行时装入依赖执行期间的地址转换。
7. 多道程序设计的目标是提高资源利用率，不意味着 CPU 同时执行多条程序指令。

## 10. 例题与解析

**例 1：** 单核处理器上两个进程交替运行，是否属于并发？是否属于并行？

**解析：** 属于并发，因为两个进程在一段时间内都能向前推进；不属于真正的硬件并行，因为单核在同一时刻只能执行一个指令流。

**例 2：** 用户程序执行读文件操作，为什么不能直接访问磁盘控制器寄存器？

**解析：** 设备寄存器属于受保护的硬件资源，直接访问可能破坏系统状态。应用程序通过系统调用请求内核执行文件读操作，内核完成权限检查、文件系统处理和设备 I/O 协调。

**例 3：** 时钟中断与缺页异常有何区别？

**解析：** 时钟中断来自处理器外部计时事件，通常用于抢占和时间片管理；缺页异常由当前指令访问的虚拟页未驻留等条件触发，需要操作系统处理页面调入或异常情形。
