## 02. 进程的概念与组成

进程是程序的一次执行过程，是系统进行资源分配和保护的基本单位。进程具有动态性、并发性、独立性和异步性。

进程控制块 PCB 是进程存在的标志，通常记录：
- 进程标识与状态；
- 程序计数器、寄存器等处理机现场；
- CPU 调度信息；
- 内存管理信息；
- 文件与 I/O 资源信息；
- 账户、权限和统计信息。

进程实体通常由程序段、相关数据段和 PCB 组成。

## 03. 进程状态与转换

经典五状态模型：
- 新建：进程正在创建；
- 就绪：除 CPU 外，其他运行条件已具备；
- 运行：正在 CPU 上执行；
- 阻塞/等待：等待某事件或资源；
- 终止：执行结束或被撤销。

常见转换：
- 就绪 → 运行：被调度选中；
- 运行 → 就绪：时间片用完或被抢占；
- 运行 → 阻塞：请求 I/O 或等待事件；
- 阻塞 → 就绪：等待事件完成；
- 运行 → 终止：执行完成或异常退出。

阻塞进程不能直接被调度执行，必须先等待事件完成回到就绪状态。

## 04. 进程控制与上下文切换

创建、撤销、阻塞、唤醒等操作由操作系统内核完成。上下文切换需要保存当前进程现场并恢复另一个进程现场，会产生管理开销。

进程切换不等于普通函数调用：它涉及特权状态、地址空间、调度信息及可能的缓存/TLB 影响。

## 05. 线程与多线程模型

线程是进程中的执行流。线程共享进程资源（如地址空间和打开文件），但通常拥有独立的线程标识、程序计数器、寄存器集合和栈。

- 用户级线程：线程管理由用户空间库完成，切换快；若采用多对一映射，一个线程阻塞可能使整个进程无法并行执行。
- 内核级线程：由内核感知并调度，线程阻塞不会必然阻塞同进程其他线程，但管理开销较大。
- 多对一、一对一、多对多模型在并行能力与管理开销方面不同。

## 06. CPU 调度层次

- 高级调度（作业调度）：决定哪些作业进入系统并创建进程。
- 中级调度（内存调度）：决定哪些进程换入/换出内存。
- 低级调度（进程调度）：从就绪队列选择进程占用 CPU。

调度评价指标：
- CPU 利用率、系统吞吐量；
- 周转时间与带权周转时间；
- 等待时间、响应时间；
- 公平性与截止期限满足情况。

周转时间：

$$
T_{\text{周转}}=T_{\text{完成}}-T_{\text{到达}}
$$

带权周转时间：

$$
W=\frac{T_{\text{周转}}}{T_{\text{运行}}}
$$

## 07. 常见调度算法

| 算法 | 核心规则 | 主要特点 |
|:---|:---|:---|
| FCFS | 按到达先后 | 简单，可能有护航效应 |
| SJF | 选择估计运行时间最短者 | 平均等待时间较优，可能饥饿 |
| 优先级调度 | 优先级最高者先执行 | 可能饥饿，可用老化缓解 |
| RR | 时间片轮转 | 交互响应较好，依赖时间片大小 |
| 多级队列 | 按类别分队列 | 队列间策略固定，灵活性有限 |
| 多级反馈队列 | 进程可在队列间移动 | 兼顾响应与长作业，规则较复杂 |

非抢占式算法在进程运行期间通常不会被其他就绪进程强制夺走 CPU；抢占式算法允许调度程序中断当前运行进程。

## 08. 进程通信

常见 IPC 方式：
- 共享内存：多个进程映射同一物理内存区域，速度快，但需同步机制保护。
- 消息传递：通过操作系统提供的发送/接收原语交换消息。
- 管道：字节流通信，普通匿名管道常用于有亲缘关系进程间。
- FIFO：命名管道，可用于无亲缘关系进程。
- 消息队列、信号量、套接字等。

信号主要用于通知事件，不等同于承载大量数据的消息通信。

## 09. 常见失分点

1. 把就绪与阻塞混淆：就绪只缺 CPU，阻塞在等待事件。
2. 把进程和程序视为同一对象。
3. 认为线程拥有完全独立的地址空间。
4. 混淆高级、中级、低级调度。
5. 周转时间与等待时间混淆，忘记周转时间包含运行时间。
6. 只记调度算法规则，不会画甘特图和计算指标。
7. 忘记共享内存仍然需要同步互斥。

## 11. 自测参考答案

1. PCB 保存进程管理与执行现场信息，是进程存在的标志。
2. 就绪态只缺 CPU；阻塞态正在等待某事件或资源。
3. 经典模型中进程是资源分配单位，线程是 CPU 调度单位；同一进程线程共享地址空间等资源。
4. 保存当前执行上下文并恢复另一个执行上下文的过程。
5. 高级调度决定作业进入；中级调度决定进程换入换出；低级调度选择 CPU 执行对象。
6. 周转时间 $=12-2=10$；带权周转时间 $=10/4=2.5$。
7. 多个进程可能并发读写共享数据，必须避免竞态和数据不一致。

## 13. 本章五大经典学习法｜进程与线程

### 13.1 费曼学习法：把进程状态变化讲成一个任务的生命周期

进程是程序的一次执行过程，不是磁盘上的程序文件。操作系统用 PCB 记录进程状态、寄存器现场、调度信息和资源信息。一个进程创建后可能进入就绪队列，获得 CPU 后运行；请求 I/O 时进入阻塞，事件完成后回到就绪，执行结束后终止。

- **就绪态**：已经具备运行条件，只缺 CPU。
- **阻塞态**：正在等待 I/O 或其他事件，不能直接被调度执行。
- **线程**：进程中的执行流；同一进程线程通常共享地址空间和打开文件，但各自有寄存器现场、程序计数器和栈。
- **上下文切换**：保存当前执行现场并恢复另一个执行现场，有管理开销。
- **调度**：决定谁何时获得 CPU；不同算法在响应、公平、吞吐和等待方面存在取舍。

**费曼复述练习：**

1. 为什么进程不是程序本身？
2. 为什么阻塞态进程不能直接变成运行态？
3. 线程共享哪些资源，通常独立拥有哪些执行现场？
4. 为什么上下文切换不是普通函数调用？
5. 周转时间为什么包含等待时间和运行时间？

**边界提醒：** “进程是资源分配单位、线程是调度单位”是经典模型下的概括；现代系统具体资源管理和调度粒度可能更复杂。线程模型的并行能力还取决于用户级/内核级映射方式。

### 13.2 西蒙学习法：按状态、调度和通信拆分

| 模块 | 内容 | 前置关系 | 达标练习 |
|---|---|---|---|
| A. 进程与 PCB | 进程实体、PCB 字段、上下文 | OS 基础 | 根据场景指出 PCB 保存的信息 |
| B. 状态与控制 | 五状态、状态转换、创建/阻塞/唤醒 | A | 画状态图并标注触发事件 |
| C. 线程 | 线程资源共享、用户/内核级线程、多对一等模型 | A、B | 比较映射模型和阻塞影响 |
| D. CPU 调度 | 调度层次、FCFS/SJF/RR/优先级/反馈队列 | B、C | 画甘特图并计算指标 |
| E. IPC | 共享内存、消息传递、管道、FIFO、套接字 | A、B | 选择合适通信方式并说明同步要求 |

**刻意练习路径：** 每道调度题先画时间轴，再算完成时间、周转时间、等待时间和响应时间；每道状态题必须写清“由哪个事件触发转换”，不要只背箭头。

### 13.3 SQ3R 阅读法：围绕状态转换与调度提问

- **Survey 浏览：** 先看 PCB 结构、五状态图、线程模型、调度算法表和 IPC 对照。
- **Question 提问：** 进程状态何时改变？阻塞为何不能直接运行？线程为何能共享资源？时间片大小如何影响 RR？共享内存为什么仍需同步？
- **Read 精读：** 对每个状态转换标出触发事件；对调度算法逐个记录抢占性、选择规则和可能问题。
- **Recite 复述：** 合上资料，画出五状态图，手算一组 RR/FCFS 调度，并口述周转时间的计算方法。
- **Review 复习：** 当天重画状态图，第 1 天做调度甘特图，第 3 天复习线程模型，第 7 天做 IPC 综合判断。

### 13.5 康奈尔笔记法：进程与线程线索卡

| 左侧线索 / 问题 | 右侧主体笔记 |
|---|---|
| 进程？ | 程序的一次执行过程，是系统进行资源分配和保护的基本单位。 |
| PCB？ | 保存进程标识、状态、处理机现场、调度、内存和 I/O 等信息。 |
| 就绪态？ | 除 CPU 外，其他运行条件已具备。 |
| 阻塞态？ | 等待某事件或资源，不能直接获得 CPU 执行。 |
| 上下文切换？ | 保存当前进程现场并恢复另一个进程现场。 |
| 线程？ | 进程内的执行流；共享进程资源，但有独立执行现场和栈。 |
| 高/中/低级调度？ | 作业进入系统、进程换入换出、选择就绪进程占用 CPU。 |
| 周转时间？ | 完成时刻−到达时刻。 |
| 带权周转时间？ | 周转时间/运行时间。 |
| 共享内存？ | 速度快，但必须用同步机制保护共享数据。 |
| 消息传递/管道？ | 通过内核提供的发送接收或字节流机制交换信息。 |

**页底总结：** 进程章节以状态转换为主线：PCB 记录执行现场，调度决定 CPU 分配，线程提供更细粒度执行流，IPC 让进程协作。调度题要画时间轴，状态题要解释触发事件。

### 13.6 五法融合自测

1. 进程从运行态请求磁盘 I/O 后通常进入什么状态？
2. I/O 完成后进程通常进入什么状态？
3. 为什么就绪态和阻塞态不能混淆？
4. 进程到达时刻 3、完成时刻 15、运行时间 4，周转时间和带权周转时间分别是多少？
5. 多对一用户级线程模型中，一个线程阻塞可能带来什么影响？
6. RR 时间片过小会带来什么额外开销？
7. 为什么共享内存仍然需要互斥/同步？

**答案要点：** 1. 阻塞态；2. 就绪态；3. 就绪只缺 CPU，阻塞在等待事件/资源；4. 周转 12，带权周转 3；5. 可能导致整个进程对应的内核执行实体阻塞，无法并行推进；6. 上下文切换频繁，调度开销增加；7. 并发访问可能产生竞态和数据不一致。
