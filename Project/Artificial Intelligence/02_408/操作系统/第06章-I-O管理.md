## 02. I/O 设备与控制器

I/O 设备通过设备控制器与总线和 CPU/内存交互。控制器包含控制逻辑、状态寄存器、数据寄存器等。设备驱动程序负责将操作系统 I/O 请求转换为设备控制器可执行的命令。

设备可按传输速率、信息交换单位、共享属性和使用方式分类。

## 03. I/O 软件层次

典型层次：
1. 用户层 I/O 软件：库函数、系统调用接口；
2. 设备独立性软件：统一命名、保护、缓冲、设备分配；
3. 设备驱动程序：设备相关控制；
4. 中断处理程序：处理中断并唤醒等待进程；
5. 硬件：控制器与设备。

设备独立性使应用程序不必依赖具体设备型号。

## 04. I/O 控制方式

### 程序查询

CPU 反复查询设备状态，直到设备就绪。实现简单，但忙等会浪费 CPU 时间。

### 中断驱动

设备完成操作或需要服务时向 CPU 发中断请求。CPU 可在设备工作期间执行其他任务，但中断处理仍有开销。

### DMA

DMA 控制器可在设备与内存间直接传送数据，CPU 主要负责初始化与完成处理。DMA 适合成块数据传输，降低 CPU 逐字节/逐字参与的开销。

## 05. 缓冲与假脱机

缓冲区用于平衡设备与 CPU 的速度差异，减少频繁中断并改善吞吐量。常见单缓冲、双缓冲、循环缓冲。

假脱机 SPOOLing 利用磁盘空间模拟独占设备，使多个进程的 I/O 请求排队，后台设备管理程序按序输出。典型例子是打印机共享。

## 06. 磁盘结构与访问时间

磁盘访问时间通常由寻道时间、旋转延迟和传输时间构成：

$$
T_{\text{access}}=T_{\text{seek}}+T_{\text{rotation}}+T_{\text{transfer}}
$$

平均旋转延迟在均匀随机等待一整圈的模型下约为半圈时间。题目若提供转速，应先计算每转时间，再取相应比例。

## 07. 磁盘调度算法

- FCFS：按请求到达顺序处理，公平简单但平均寻道可能较大。
- SSTF：选择距离当前磁头最近的请求，平均寻道较小，但远端请求可能饥饿。
- SCAN：磁头沿一个方向移动，处理经过的请求，到端点后反向。
- C-SCAN：只在一个方向处理请求，到端点后快速返回起点方向，等待时间更均匀。
- LOOK：类似 SCAN，但到该方向最后一个请求处就反向，不必到物理端点。
- C-LOOK：类似 C-SCAN，只在请求范围内循环。

计算总磁头移动量时，逐项写出磁道访问顺序并累加相邻差值；不要将移动量与实际时间直接混淆。

## 08. 常见失分点

1. 将程序查询与中断驱动混淆。
2. 认为 DMA 完全不需要 CPU 参与；CPU 仍需初始化和完成处理。
3. 把缓冲与假脱机当成同一机制。
4. 磁盘访问时间遗漏旋转延迟或传输时间。
5. SCAN 与 LOOK、C-SCAN 与 C-LOOK 的端点行为混淆。
6. SSTF 可能导致远端请求饥饿。
7. 总磁头移动量没有按实际访问顺序逐段求和。

## 10. 自测参考答案

1. CPU 反复轮询设备状态，形成忙等。
2. DMA 可由控制器直接完成设备与内存间成块传输，CPU 无需逐字/逐字节参与。

7. $60/7200=1/120$ 秒，约 8.33 ms。

## 12. 本章五大经典学习法｜I/O 管理

### 12.1 费曼学习法：解释一次 I/O 请求如何完成

应用程序发出 I/O 请求后，操作系统通过设备独立性软件和驱动程序把请求转换成设备控制器可以执行的操作。设备控制器与外设交互，完成后通过中断或状态寄存器通知 CPU。

- **程序查询**：CPU 主动反复检查设备状态，简单但忙等。
- **中断驱动**：设备需要服务或完成操作时通知 CPU，CPU 可在等待期间运行其他任务。
- **DMA**：CPU 初始化 DMA 控制器后，由控制器在设备与内存之间完成成块传输。
- **缓冲**：用内存区域平衡 CPU 与设备速度，减少频繁等待。
- **SPOOLing**：利用磁盘队列模拟独占设备，让多个进程共享打印机等设备。
- **磁盘调度**：安排请求访问顺序，减少磁头移动或改善等待公平性。

**费曼复述练习：**

1. 为什么操作系统需要设备驱动程序？
2. 程序查询为什么会忙等？
3. 中断驱动为什么仍有 CPU 处理开销？
4. DMA 为什么适合成块数据传输？
5. 缓冲与 SPOOLing 分别解决什么问题？
6. 为什么磁头移动量不等于完整磁盘访问时间？

**边界提醒：** DMA 需要 CPU 初始化并处理完成状态；磁盘访问时间还包括旋转延迟和传输时间；SCAN/LOOK 等算法的移动量必须按题目规定的初始方向和边界计算。

### 12.2 西蒙学习法：拆分 I/O 知识块

| 模块 | 内容 | 前置关系 | 达标练习 |
|---|---|---|---|
| A. 设备与控制器 | 设备类型、控制器寄存器、驱动程序 | OS 基础 | 画设备到 CPU/内存的连接图 |
| B. I/O 软件层次 | 用户层、设备独立层、驱动、中断处理、硬件 | A | 将功能放到对应层次 |
| C. 控制方式 | 程序查询、中断、DMA | A、B | 比较 CPU 参与程度并画时序 |
| D. 缓冲与 SPOOLing | 单/双/循环缓冲、假脱机 | C | 分析生产者/消费者与设备队列 |
| E. 磁盘管理 | 访问时间、旋转延迟、磁盘调度 | A—D | 计算时间和总磁头移动量 |

**刻意练习路径：** I/O 流程题先标出请求从用户层到设备硬件的路径；磁盘调度题先写初始磁头位置、初始方向和请求序列，再逐段计算移动量。

### 12.3 SQ3R 阅读法：围绕控制权和等待时间提问

- **Survey 浏览：** 先看 I/O 软件层次图、三种控制方式比较、缓冲/SPOOLing 和磁盘调度算法表。

- **Review 复习：** 当天复习控制方式，第 1 天重画 SPOOLing，第 3 天计算磁盘访问时间，第 7 天重做磁盘调度。

### 12.4 番茄工作法：五个番茄完成 I/O 管理

| 番茄 | 25 分钟任务 | 可验收产出 |
|---|---|---|
| 1 | 设备、控制器和 I/O 软件层次 | 画出从系统调用到设备硬件的分层图 |
| 2 | 程序查询、中断、DMA | 对比三种流程并标出 CPU 工作阶段 |
| 3 | 缓冲与 SPOOLing | 画双缓冲时序和打印队列流程 |
| 4 | 磁盘访问时间 | 完成 4 道寻道/旋转/传输时间题 |
| 5 | 磁盘调度 | 对同一请求序列计算 FCFS、SSTF、SCAN、LOOK 等移动量 |

每轮休息 5 分钟。磁盘调度必须把磁头移动序列写完整；只写最终总磁道数、不列出相邻移动过程，容易漏算。

### 12.5 康奈尔笔记法：I/O 管理线索卡

| 左侧线索 / 问题 | 右侧主体笔记 |
|---|---|
| I/O 软件层次？ | 用户层、设备独立性软件、设备驱动、中断处理程序、硬件。 |
| 程序查询？ | CPU 轮询设备状态，简单但忙等。 |
| 中断驱动？ | 设备发中断请求，CPU 响应并执行中断服务程序。 |
| DMA？ | CPU 初始化，DMA 控制器直接在设备与内存间成块传输，结束后通知 CPU。 |
| 缓冲？ | 用内存暂存数据，协调 CPU 与设备速度，减少频繁等待。 |
| SPOOLing？ | 用磁盘队列和后台程序模拟独占设备共享。 |
| 磁盘访问时间？ | 寻道时间+旋转延迟+传输时间。 |
| 平均旋转延迟？ | 均匀随机等待模型下约为半圈时间。 |
| FCFS/SSTF？ | 按到达顺序；选择当前距离最近请求，SSTF 可能饥饿。 |
| SCAN/LOOK？ | SCAN 到端点再反向；LOOK 到该方向最后一个请求就反向。 |
| C-SCAN/C-LOOK？ | 单向服务后循环返回；C-LOOK 只在请求范围内循环。 |

**页底总结：** I/O 管理的关键是控制权由谁掌握、CPU 何时参与、数据如何缓冲，以及设备请求如何排序。控制方式比较要关注 CPU 参与程度；磁盘题要分开计算寻道、旋转和传输时间。

### 12.6 五法融合自测

1. 程序查询为什么会造成 CPU 忙等？
2. DMA 传输前后 CPU 分别负责什么？
3. 缓冲与 SPOOLing 的主要差异是什么？
4. 磁盘访问时间由哪三部分组成？
5. 7200 rpm 的磁盘每转一圈需要多少 ms？平均旋转延迟是多少？
6. SSTF 可能造成什么问题？
7. LOOK 与 SCAN 的反向时机有何不同？
8. 请求序列中总磁头移动量为什么要按相邻磁道差值累加？

**答案要点：** 1. CPU 持续轮询设备状态；2. 传输前配置源/目的地址、长度、方向并启动，传输后处理中断/状态；3. 缓冲在内存中协调速度，SPOOLing 用磁盘队列模拟独占设备共享；4. 寻道、旋转延迟、传输；5. 一圈 60/7200 s≈8.33 ms，平均约 4.17 ms；6. 远端请求可能饥饿；7. SCAN 到物理端点，LOOK 到当前方向最后一个请求；8. 总移动量是实际访问路径上每一段移动距离之和。
